Problema y propuesta de valor

Problema observado

En clinicas pequenas y medianas del Peru, los medicos invierten 30-40% de la consulta escribiendo notas en lugar de atender al paciente. Las historias clinicas suelen ser:

  • Incompletas por presion de tiempo.
  • Inconsistentes en estructura entre medicos.
  • Dificiles de auditar.
  • No reutilizables para reportes.

Solucion: MedScribe AI

Plataforma SaaS multi-tenant donde el medico:

  1. Graba la conversacion con el paciente.
  2. La IA transcribe y opcionalmente identifica hablantes.
  3. Otra IA genera la nota SOAP estructurada en 7 secciones.
  4. El medico revisa, firma digitalmente y exporta a PDF/Word.

Resultado: el medico recupera tiempo y la historia clinica es uniforme, completa y auditable.

Arquitectura del sistema

Tres servicios independientes orquestados con Docker Compose. Comunicacion HTTP entre ellos. Frontend nunca llama a IA directamente con secretos.

cliente-web

Angular 17 + Tailwind. SPA con 13 rutas y lazy loading. Bundle inicial 98 KB.

gateway-java

Spring Boot 3.3. JWT con HS512. Spring Data JPA. 7 controladores REST.

servicio-ia

FastAPI. Cascade Whisper de 4 proveedores y cascade LLM de 8 proveedores.

Base de datos (MySQL 8)

14 tablas en 3FN, indices unicos, FKs con integridad referencial y multi-tenant por columna IdClinica. Ver el diagrama 4 de la seccion anterior.

Decisiones clave

DecisionPor que
FK simples (Long) sin relaciones bidireccionales JPAEvita problema N+1 y simplifica DTOs.
Multi-tenant por IdClinicaAislamiento fisico de datos entre clinicas.
LONGTEXT en NotaClinicaEstructuradaTEXT (65 KB) era insuficiente para notas largas.
Indices unicos en correo y RUCLogin O(log n) y evitar duplicados.
ddl-auto=none en produccionEl script SQL es la fuente de verdad, no Hibernate.

Interceptor JWT

export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const token = localStorage.getItem('token');
  if (token) {
    const peticion = req.clone({ setHeaders: { Authorization: `Bearer ${token}` } });
    return next(peticion);
  }
  return next(req);
};

Seguridad

Autenticacion

JWT firmado con HS512. Token incluye idUsuario, idClinica, rol y permisos.

Contrasenas

BCrypt con factor 10. Salt aleatorio por hash.

Multi-tenant

idClinica viene del JWT, no del cliente.

Secretos

API keys solo en .env del servicio Python. Excluido del repo.

CORS

Configurado en Spring para aceptar solo el origen del frontend.

Validacion

DTOs con @Valid en backend. Validaciones (DNI, RUC, correo) en frontend.
